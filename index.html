Genie Agents & Supervisor Best Practices

Design, CI/CD, observability, and multi-agent operating patterns.

Genie space delivery

  • Use curated tables, clear metric definitions, and strong examples
  • Store prompts, instructions, and benchmark questions in Git
  • Run benchmark regressions before promoting environment changes
  • Use dev, test, and production promotion gates for safer rollout

Supervisor patterns

  • Use Supervisor Agent for multi-domain questions across tools or subagents
  • Write precise tool and subagent descriptions for better routing
  • Apply least-privilege access so users only reach permitted sources
  • Keep examples current and representative of executive workflows

What Genie Workbench scores — the IQ Scanner (12 checks)

Each space gets a 0–12 score across three tiers: Not Ready → Ready to Optimize (checks 1–10) → Trusted (all 12). Baseline every space here before wiring it into a Supervisor.

1 · Agent descriptionClear top-level description — also drives supervisor routing
2 · Table descriptions≥80% of tables described (auto-enriched from Unity Catalog)
3 · Column descriptions≥50% of columns described
4 · InstructionsBusiness-context text instructions present
5 · Join specifications≥1 join defined when multiple tables are configured
6 · Focused scopeBetween 1 and 12 tables / metric views — keeps the space tight
7 · SQL guidance≥1 of: SQL functions, expressions, measures, filters, example SQL
8 · Entity / format matching≥1 column with value/format assistance for accurate filters
9 · Benchmark questions≥10 benchmark questions for measurable accuracy
10 · Column noise controlNoisy / internal columns hidden from the model
11 · Optimization runA completed Auto-Optimize run exists
12 · Accuracy ≥ 85%Best optimized benchmark accuracy clears the bar

Best practices these checks encode

  • Prefer structured context (descriptions, synonyms, joins, example SQL) over long free-text prompts
  • Keep each space small and domain-focused — aim for 5 or fewer sources
  • Describe tables and columns in business language; hide noisy technical fields
  • Define joins explicitly — don't let Genie guess relationships
  • Build a benchmark of ≥10 (ideally ≥30) representative questions and measure accuracy
  • Set a strong agent description — it doubles as the Supervisor's routing signal

How to apply it

  • Scan each existing Genie space to get a baseline IQ score
  • Close the failing checks (descriptions, joins, benchmarks) to reach "Ready to Optimize"
  • Run Auto-Optimize to push benchmark accuracy past 85%
  • Only then add the space to a Supervisor — quality first, orchestration second
  • Re-scan after schema changes to catch drift

Genie Workbench is a Databricks "solutions" project — community-supported via GitHub, not official Databricks support.

Directing the Supervisor Agent — routing that doesn't get lost

A Supervisor routes each question to one child agent based on its description. Misrouting is almost always a description / instruction problem — not a model problem.

Master prompt (supervisor instructions)

  • State the supervisor's role and explicit routing rules ("bookings & revenue → Travel Analytics Genie; policy → Knowledge Assistant")
  • Tell it to ask a clarifying question when a request is ambiguous or spans domains
  • Define a fallback for out-of-scope questions so it degrades gracefully
  • Keep it to global behavior — domain facts belong in the child agents, not here

Tool & agent descriptions

  • Make each description specific and non-overlapping — "Corporate-travel bookings: volume, revenue, TMC performance by region", not "travel data"
  • Distinct boundaries stop two agents from both looking like the right target
  • Every Genie space needs its own strong description (IQ check #1)
  • The description is the routing signal — invest in it

Examples, tools & skills

  • Add example questions paired with the expected agent — the highest-leverage fix for stubborn misrouting
  • Reuse governed Unity Catalog functions and AI skills as tools for actions, not just Q&A
  • Attach external systems via MCP connections for write / operational tasks
  • Test with real phrasings and sharpen descriptions where routing misses

Scale with hierarchy

  • Group related Genie spaces under domain sub-supervisors, then a top supervisor over those
  • Smaller routing decisions at each level = less "lost context"
  • Apply least-privilege so users only reach permitted sources
  • A supervisor can't rescue a weak Genie space — get each to "Trusted" first

Reusable, governed tools & AI skills — Unity Gateway

Register once, reuse everywhere. Unity Gateway extends Unity Catalog governance to runtime AI — models, MCP servers, tools/functions, and agents become governed, shareable building blocks a Supervisor can call.

AI assets as Unity Catalog securables

  • Register models, MCP servers, UC functions/tools, and agents as governed objects
  • Control access with standard Unity Catalog grants — least privilege by default
  • Rate limits, guardrails, usage tracking, cost attribution, and audit logging
  • Share a tool once — any authorized agent can reuse it
Unity Gateway docs →

How it strengthens the Supervisor

  • Add governed tools to the Supervisor as UC functions, MCP connections, Genie spaces, or agent endpoints
  • The Supervisor inherits the caller's permissions — it can only invoke what the user may access
  • Reusable skills mean less duplication and consistent governance across every agent
  • Every tool call is auditable end to end

Agent Memory

Give your agents persistence — short-term session state and long-term semantic recall, powered by Lakebase.

Managed Memory

Databricks handles storage, indexing, and lifecycle automatically. Ideal for production agents where you want zero infrastructure overhead.

  • Built-in checkpoint store for resumable conversation threads
  • Semantic memory with pgvector-backed embeddings via Databricks endpoints
  • Automatic TTL, compaction, and garbage collection
  • No infrastructure to provision — just configure project, branch, and schema
Managed Memory Docs →

Self-Managed Memory

Bring your own storage backend when you need full control over the persistence layer, custom retention policies, or hybrid architectures.

  • Plug in any checkpoint or store backend (Redis, Postgres, custom)
  • Full control over schema, indexing, and eviction strategies
  • Suitable for multi-cloud or air-gapped deployments
  • Use alongside managed memory for hybrid patterns
Self-Managed Memory Docs →

Initializing Agent Memory with LangGraph

The databricks_langchain package provides async-ready checkpoint and store classes that wire directly into LangGraph’s persistence layer.

agent_memory.py 
from databricks_langchain import AsyncCheckpointSaver, AsyncDatabricksStore

# Short-term: thread/session checkpoints — resumable runs.
async with AsyncCheckpointSaver(
    project=PROJECT,
    branch=BRANCH,
    schema=SCHEMA,
) as checkpointer,
AsyncDatabricksStore(
    # Long-term + semantic: pgvector-backed memory,
    # embedded via a Databricks endpoint.
    project=PROJECT,
    branch=BRANCH,
    schema=SCHEMA,
    embedding_endpoint="databricks-gte-large-en",
    embedding_dims=1024,
) as store:
    yield checkpointer, store

Key Concepts

  • AsyncCheckpointSaver — persists LangGraph thread state so conversations survive restarts
  • AsyncDatabricksStore — semantic key-value store backed by pgvector for long-term recall
  • Embedding endpoint — uses Databricks model serving (e.g. databricks-gte-large-en) for vector similarity
  • Project / Branch / Schema — Lakebase coordinates that isolate memory per environment

When to Use Each

  • Checkpoints only — stateful multi-turn chat, tool-calling agents with resumable sessions
  • Store only — user preferences, learned facts, cross-session context
  • Both together — production agents that remember the current thread and recall past interactions
